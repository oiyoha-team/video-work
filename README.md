# 퍼포먼스 영상 자동화

레퍼런스 영상을 분석해 자사 제품용 퍼포먼스 광고 영상을 만드는 도구입니다.

| 모듈 | 화면 단계 | 상태 |
|---|---|---|
| 1 기획 자동화: 레퍼런스 분석 → 제품 입력 → 스크립트 생성·수정 → 확정 | 1~4 | ✅ 사용 가능 |
| 2-A 비주얼: 장면 이미지 생성 → 영상화 | 5 | ✅ 힉스필드 (키 없으면 임시 엔진) |
| 2-B 사운드: 대사 음성(TTS) | 5 (비주얼과 동시) | ✅ 타입캐스트 (키 없으면 OS 기본 음성) |
| 3 결과물 다운로드: 클립·음성·이미지·자막 전체/선택 다운로드 → 직접 편집 | 6 | ✅ 사용 가능 |
| 승인 알림: 단계 완료 시 [진행]/[수정] | 전체 | ✅ 앱 알림 · Flow 연동 예정 |

- 전체 흐름 한눈에 보기: **[WORKFLOW.html](WORKFLOW.html)** (브라우저로 열기)
- 설계와 모듈 간 데이터 형식: [PLAN.md](PLAN.md)

## 처음 설치하기 (스타터팩)

미리 설치해 둘 프로그램은 없습니다. 아래 파일 하나만 실행하면 필요한 것을 확인하고, 없는 것은 자동으로 설치합니다.

| | Windows | Mac |
|---|---|---|
| 1. 설치 (처음 한 번) | `1_설치하기.bat` 더블클릭 | `1_설치하기.command` 더블클릭 |
| 2. 실행 (매번) | `2_실행하기.bat` 더블클릭 | `2_실행하기.command` 더블클릭 |

**스타터팩이 하는 일**
0. **OS를 자동 판별합니다.** Mac이면 Homebrew·`.command` 방식, Windows면 winget·`.bat` 방식으로 진행합니다.
   - 다른 OS용 파일을 실행해도 맞는 방식으로 자동 전환됩니다. 예를 들어 Windows에서 `.command`를 실행하면 Windows 설치로 넘어갑니다.
   - Mac은 Apple Silicon과 Intel을 구분하고, 인터넷에서 받은 파일에 붙는 격리 표시를 풀고 실행 권한을 줍니다.
1. 필수 프로그램을 확인하고, 없으면 설치합니다.
   - Python 3.10 이상 (없으면 3.12 설치)
   - Node.js 18 이상 (없으면 LTS 설치)
   - Visual C++ 런타임 (Windows만, 음성 인식 엔진에 필요)
   - ffmpeg는 Python 패키지에 포함되어 있어 따로 설치하지 않습니다.
2. Python 가상환경을 만듭니다. 다른 PC에서 복사해 온 `.venv`가 있으면 확인한 뒤 새로 만듭니다.
3. Python 패키지를 설치합니다.
4. 화면을 빌드합니다.
5. `.env` 파일을 만들고 Claude API 키를 묻습니다. 없으면 Enter로 건너뛸 수 있습니다.
6. 음성 인식 모델(약 500MB)을 미리 받습니다. 받을지 선택할 수 있습니다.
7. 최종 점검 후 바로 실행할지 묻습니다.

여러 번 실행해도 안전합니다. 설치 중 오류가 나면 창을 닫고 다시 실행하세요. 이미 설치된 것은 건너뜁니다.

**설치 중 알아둘 것**
- Windows: Node.js나 Visual C++ 런타임을 설치할 때 관리자 권한 창이 뜨면 '예'를 누르세요.
  - winget이 없는 구형 Windows 10은 Microsoft Store에서 '앱 설치 관리자'를 먼저 설치해야 합니다.
- Mac: Homebrew를 설치할 때 Mac 로그인 비밀번호를 묻습니다.
  - 더블클릭해도 실행되지 않으면 터미널에서 `bash 1_설치하기.command`로 실행하세요.

**API 키:** 나중에 넣으려면 `.env` 파일을 열고 아래 줄에 키를 붙여 넣은 뒤 프로그램을 다시 실행하세요.
```
ANTHROPIC_API_KEY=sk-ant-...
```
키가 없으면 **mock 모드**로 동작합니다. 음성 인식(대사 추출)은 그대로 되고, 장면 분석이나 스크립트 생성처럼 Claude가 필요한 기능은 직접 입력하거나 레퍼런스를 복사한 초안으로 대체됩니다.

## 팀원에게 배포하기

1. 저장소를 받습니다: `git clone https://github.com/oiyoha-team/video-work.git`
2. **`.env` 파일은 저장소에 없습니다.** API 키가 노출되지 않도록 git에서 제외했습니다.
   - 담당자에게 받은 `.env`를 프로젝트 폴더(`1_설치하기` 파일이 있는 곳)에 넣고 설치하면, 설치 파일이 그 키를 그대로 씁니다.
   - `.env`가 없으면 설치 중에 API 키를 묻습니다. 키가 `sk-ant-usr-`로 시작하면 워크스페이스 ID(`wrkspc_…`)도 이어서 묻습니다.
   - `.env`는 메신저 개인 메시지처럼 공개되지 않는 경로로만 전달하세요. 공개 저장소나 단체방에 올리면 키가 무단 사용될 수 있습니다.
3. `1_설치하기`를 실행하고, 이후에는 `2_실행하기`만 실행합니다.

## 새 버전으로 업데이트하기

1. GitHub(https://github.com/oiyoha-team/video-work)에서 **Code → Download ZIP**으로 새 버전을 받습니다.
2. 압축을 풀고, 안의 파일을 **지금 쓰는 프로그램 폴더에 덮어씁니다** ("모두 바꾸기").
   - `.env`(API 키)와 `data` 폴더(프로젝트·제품 템플릿)는 ZIP에 없으므로 그대로 남습니다.
   - 새 폴더에 따로 풀면 설치를 처음부터 다시 해야 하고, 기존 프로젝트도 보이지 않습니다.
3. `2_실행하기`를 실행합니다. 바뀐 부분이 있으면 실행 전에 자동으로 반영됩니다.
   - 새로 생긴 설정 칸을 `.env`에 추가합니다.
   - 비어 있는 API 키(힉스필드·타입캐스트)를 물어봅니다. 붙여넣고 Enter를 누르세요.
   - 필요한 패키지를 설치하고 화면을 새로 만듭니다. 처음 한 번은 1~2분 걸릴 수 있습니다.
4. 화면 왼쪽 위의 버전(예: `v2026.11.24`)이 새 버전과 같은지 확인합니다.
   - 예전 프로그램 창을 켜 둔 채 업데이트해도 괜찮습니다. `2_실행하기`가 예전 프로그램을 알아채고 끈 뒤 새 버전으로 실행합니다.
   - 그래도 버전이 그대로라면 브라우저에서 `Ctrl + F5`를 눌러 새로고침하세요.

> 2026.11.20 이전 버전에는 이 자동 반영 기능이 없습니다. 그 버전을 쓰다가 처음 업데이트할 때는 덮어쓴 뒤 `1_설치하기`를 한 번 실행하세요. 그다음부터는 `2_실행하기`만 실행하면 됩니다.

## 실행하기

`2_실행하기`를 실행하면 브라우저에서 http://localhost:8000 이 열립니다.
- 실행 창을 닫으면 프로그램도 종료됩니다.
- 이미 실행 중이면 브라우저만 다시 엽니다.

> `.env`를 수정했다면 실행 창을 닫고 다시 실행해야 반영됩니다.

## 사용 흐름

1. **레퍼런스 분석**: 3분 이하 영상을 올립니다.
   - 2초 단위로 장면, 대사, 자막, 역할을 추출하고, 영상 전체의 말투·컨셉·화자 페르소나도 정리합니다.
   - 바로 이어지는 구간의 대사가 **완전히 같을 때만** 한 구간으로 합칩니다.
   - 대사는 **문장 단위**로 끊어 한 줄에 한 문장씩 보여 줍니다.
   - 분석 대상은 **대사와 장면**입니다(자막은 분석하지 않음).
   - **장면 상세:** 구간마다 피사체·인물, 행동·표정, 장소·배경, 구도·카메라 앵글, 조명·색감, 제품 노출을 추출합니다. 영상 전체의 **비주얼 스타일**도 함께 정리합니다.
   - 장면 분석은 `scene_analysis/` 폴더에 따로 저장했다가, 영상 제작 단계에서 그림체·구성을 참고할 때 씁니다(장면을 그대로 복사하지 않음).
     - 마침표(.), 물음표(?), 느낌표(!)를 문장 끝으로 봅니다.
     - 한 문장은 한 구간에만 들어갑니다.
   - 결과는 모든 칸을 직접 고칠 수 있습니다.
   - 영상 비율은 레퍼런스에서 자동으로 감지하고, 1:1 / 4:5 / 16:9 / 9:16 중에서 바꿀 수 있습니다.
2. **제품 정보**: 제품 정보 입력서 양식을 따릅니다.
   - **입력 항목:** 1 제품명, 2 제품 USP, 3 제품 특징, 4 사회적·수치적 근거 및 권위, 5 제품 지칭 키워드, 6 들어가면 안 되는 표현, 7 상세페이지 URL, 그리고 기타 메모
   - **이미지:** 연출컷과 누끼컷을 각각 **최대 5장**까지 넣을 수 있고, 여러 장을 한 번에 고를 수 있습니다.
   - **입력 방법:**
     - 직접 입력
     - 저장된 제품 불러오기: 한 번 [제품 저장]을 해 두면 다음 기획안에서 다시 쓸 수 있습니다.
     - md 파일 업로드: [템플릿 받기]로 받은 양식([product_template.md](product_template.md))을 쓰면 정확하게 읽습니다. 6번이 '없음'이면 빈 값으로 처리합니다.
3. **스크립트 작성**: 레퍼런스 구조와 말투를 유지한 채 제품 내용으로 바꾼 **대사 스크립트**가 생성됩니다.
   - 화면에는 레퍼런스 대사와 자사 대사만 나란히 보입니다.
   - 대사는 레퍼런스 문장과 **1:1**로 바뀝니다(한 줄 = 한 문장). 문장 수가 다르면 빨간색으로 표시됩니다.
   - 왼쪽에서 직접 수정하거나, 오른쪽 Claude 대화창에서 요청합니다. 대화창의 변경안은 [적용]을 눌러야 반영됩니다.
4. **기획 확정**: 최종본은 **대사만** 한 줄에 한 문장씩 보여 줍니다. [TXT 저장]이나 [전체 복사]로 가져갑니다.
   - [영상 제작으로 넘기기]를 누르면 5단계가 시작됩니다.
5. **영상 제작**: 비주얼(장면 이미지 → **전체 승인** → 영상화)과 사운드(대사 음성)가 동시에 진행됩니다. 승인은 장면마다 하지 않고 **전체 승인**이 기본입니다. 아무것도 자동으로 시작하지 않고, 화면에서 직접 시작합니다.
   - **이미지 → 전체 승인 → 영상:** 이미지를 확인하고 마음에 안 드는 장면만 다시 만든 뒤 [이미지 전체 승인 → 영상화]를 누르면 영상화가 시작됩니다. 영상화 뒤에 이미지를 다시 만든 장면은 영상이 지워지고, 다시 전체 승인하면 그 장면만 영상화합니다.
   - **크게 보기:** 이미지나 영상을 누르면 전체화면으로 열립니다. ← → 로 장면을 넘기고 Esc로 닫습니다.
   - **레퍼런스는 참고만 합니다(복사하지 않음):** 레퍼런스에서 **그림체·질감·색감, 화자 페르소나, 컨셉, 후킹 방식, 전개 구성**만 빌려 오고, 인물·배경·소품·장면 구도는 새로 만듭니다. 예를 들어 3D 애니메이션 그림체의 숏폼이면 같은 느낌의 그림체와 후킹으로, 완전히 새로운 장면과 캐릭터를 만듭니다.
     - 먼저 **첫 장면(기준 장면)**을 레퍼런스 그림체 견본과 제품 사진으로 만듭니다. 레퍼런스 장면 자체는 이미지 AI에 넘기지 않습니다.
     - 나머지 장면은 **기준 장면 + 제품 사진**을 참고해 그림체·인물·분위기가 이어지게 만듭니다.
     - 무엇을 빌려 오고 무엇을 새로 만들었는지 5단계 상단 [레퍼런스에서 빌려 온 것 · 새로 만든 것]에 정리됩니다.
   - **수정 지시 넣어 다시 만들기:** 장면마다 [↻ 이미지 수정]·[↻ 영상 수정]을 누르면 수정 지시를 적는 칸이 열립니다(예: "제품을 두 손으로 들고 카메라 쪽으로", "배경을 밝은 욕실로"). Claude가 지시를 장면 프롬프트에 정확히 반영해 다시 만듭니다. 비워 두면 같은 설계로 다시 만듭니다.
   - **여러 장면 골라 한 번에:** 장면 왼쪽 체크박스로 여러 장면을 고르면 위쪽 막대에서 같은 수정 지시로 [이미지 / 영상 / 음성 다시 만들기]를 할 수 있습니다.
   - **이전 / 새 결과 비교:** 다시 만든 장면은 이전 결과와 새 결과가 나란히 보입니다. [이전 것 사용] 또는 [새 것 사용]으로 고릅니다. 고르지 않고 전체 승인하면 새 결과로 확정됩니다.
   - **진행 표시:** 작업을 시작하면 로딩바, 경과 시간, **남은 시간(최소~최대)**이 바로 보입니다. 장면마다 "만드는 중 · 35초 경과 · 보통 30초~2분"이 표시됩니다. 남은 시간은 실제로 걸린 시간을 기록해 점점 정확해집니다.
   - **오류 안내:** 실패하면 장면 아래에 **원인과 해결 방법**이 함께 나옵니다(예: 크레딧 부족, 키 오류, 부적절 판정, 서비스 혼잡). 원래 오류 문구는 [오류 원문 보기]에 있습니다.
   - **초기화:** 5단계 아래 [이미지·영상 초기화] [음성 초기화] [영상 제작 단계 전체 초기화]로 만든 결과를 지우고 다시 시작합니다(고른 모델·목소리는 유지). 상단 [프로젝트 초기화]는 이름만 남기고 1단계부터 다시 시작합니다(제품 정보는 남길지 고름).
   - **음성 설정:** 생성 전에 목소리·배속을 고르고 [이 설정으로 첫 문장 미리 듣기]로 확인한 뒤 [음성 생성 시작]을 누릅니다.
     - 목소리는 **성별·연령**으로 거르고, 타입캐스트 목소리 이름과 샘플 음성을 그대로 보고 들으며 고릅니다.
   - **음성 다시 만들기:** 마음에 안 드는 문장은 [↻ 이 문장만]으로 그 문장만 다시 만듭니다(현재 설정 적용).
   - **전체 승인 → 다음 단계:** 모든 장면에 영상 클립과 음성이 있으면 [전체 승인 · 결과물 받기]로 넘어갑니다.
   - 이미지를 만들기 전에 **장면 브리프**(영어 이미지 프롬프트와 카메라 움직임)를 만듭니다. 재료는 장면 분석, 자사 대사, 제품 정보입니다.
   - 제품 연출컷·누끼컷은 장면에 배정하지 않습니다. 제품 외형을 정확히 그리기 위한 **참고 자료**로 모두 넘깁니다.
   - **새 인물:** 레퍼런스 인물을 그대로 쓰지 않습니다. 성별·연령대·페르소나만 비슷하고 얼굴·헤어·의상이 다른 새 인물을 설정합니다. 첫 장면에 인물이 나오면 그 인물이 기준이 되고(바꾸려면 첫 장면을 다시 만듦), 첫 장면에 인물이 없으면 첫 장면의 그림체로 인물 기준 이미지를 따로 만듭니다.
   - **제품 크기·합성:** 손에 든 제품 사진으로 실제 크기를 읽어 그 크기로 그리고, 장면의 빛·색감·그림자·재질에 맞춰 실제로 들고 찍은 것처럼 만듭니다. 제품 정보 '추가 정보'에 크기(예: 파우치 8×8cm)를 적어 두면 더 정확합니다.
   - 음성은 **자사 스크립트 문장마다 파일 하나**로 만들어집니다(`scene01_1.wav`, `scene01_2.wav` …).
     - 레퍼런스 영상의 음성은 대사 추출에만 쓰고, 파일로 내보내지 않습니다.
   - 문장 음성 길이의 합이 장면 길이보다 길면 빨간색으로 표시됩니다.
6. **결과물 다운로드**: 장면별 영상 클립, 음성(TTS), 이미지, 편집용 자료를 받아 편집 툴에서 직접 완성합니다.
   - **받는 방법:** 전체 ZIP, 묶음별 ZIP(영상만, 음성만 등), 체크한 파일만 ZIP, 파일 하나씩 받기를 모두 지원합니다.
   - **파일 이름:** `scene01`, `scene02` … 처럼 장면 순서대로 붙어 있습니다.
   - **편집용 자료:**
     - `…_premiere.xml` ★: **프리미어 타임라인.** 가져오면 영상(V1)·음성(A1)이 이미 제 시간에 깔린 시퀀스가 열립니다. 음성이 클립보다 길어 늘어난 장면은 클립 마지막 화면(정지 화면)으로 채워 두고, 영상 없이 이미지만 만든 장면은 이미지를 장면 길이만큼 놓습니다.
     - `…_subtitles_premiere.srt` ★: 실제 음성 길이에 맞춘 프리미어용 자막입니다.
     - `timeline.csv`: 장면별 시작·끝 시간, 대사, 파일 이름을 정리한 **참고용 표**입니다(고쳐도 프리미어에는 반영되지 않음).
     - `subtitles.srt`: 레퍼런스 장면 시간 기준 자막입니다.
   - **프리미어 편집 순서:**
     1. **전체 ZIP**을 받아 폴더 구조 그대로 압축을 풉니다.
     2. 프리미어 [파일 > 가져오기]로 `…_premiere.xml`을 엽니다. 생긴 시퀀스를 더블클릭하면 끝입니다. [미디어 연결] 창이 뜨면 [찾기]로 파일 하나만 고르면 나머지는 자동으로 연결됩니다.
     3. `…_subtitles_premiere.srt`를 가져와 타임라인 맨 앞(0초)에 끌어다 놓으면 자막이 음성과 맞게 깔립니다.
     - XML만 골라 받아도 XML이 쓰는 영상·음성·정지 화면이 ZIP에 함께 들어갑니다.

**5단계 엔진 (`.env`에 키가 있으면 자동 사용)**
- **모델 선택:** 이미지 모델과 영상 모델을 5단계 화면에서 직접 고릅니다. 가격도 함께 보입니다.
  - **화질:** 모든 이미지·영상은 1080p 이상으로 만듭니다. 이미지는 2k(9:16 기준 약 1512×2688), 영상은 1080p(1080×1920)로 요청합니다. 1080p를 낼 수 없는 모델(예: Kling 3.0 Standard, Kling 4.0 Flash)은 목록에 나오지 않습니다.
  - 모델 목록은 힉스필드에서 **12시간마다 자동으로 갱신**되므로, 새 모델이 나오면 따로 손대지 않아도 목록에 나타납니다. [지금 갱신]으로 바로 받을 수도 있습니다.
  - 기본값은 이미지 GPT Image 2.5 Flare(힉스필드 목록 이름: Marketing Studio Image · flare), 영상 Kling 2.5 Turbo Pro입니다(목록에 ★ 추천 표시).
- **이미지:** 그림체·배경 설정·장면 설계와 함께 참고 이미지를 넘깁니다. 첫 장면은 레퍼런스 그림체 견본 1장(인물·배경·구도는 쓰지 말라고 지시) + 제품 사진, 나머지 장면은 기준 장면 + 제품 사진입니다.
  - 참고 이미지는 **최대 5장**입니다. 6장 이상 넣으면 생성이 실패하는 것을 확인했습니다.
- **영상:** 클립 길이는 장면 길이에 맞춥니다. 모델 최소 길이보다 짧은 장면은 최소 길이로 만듭니다. 영상 모델이 만드는 소리는 끕니다.
- **비용:** 이미지·영상은 비용이 들어서 5단계에 들어가도 자동으로 시작하지 않습니다. 화면의 **예상 비용**을 확인하고 직접 시작하며, 시작할 때 한 번 더 확인 창이 뜹니다.
- **음성:** 타입캐스트(ssfm-v31). 자사 스크립트를 문장마다 음성으로 만들고, 앞뒤 문장을 함께 넘겨 자연스럽게 읽게 합니다.
  - 목소리를 고르지 않으면 화자 페르소나(성별·연령)에 맞춰 자동으로 고릅니다.
  - 화면에서 **성별·연령**으로 거른 뒤, 타입캐스트 목소리 이름 옆 ▶로 **샘플을 듣고** 고릅니다. 배속(0.5~2배)도 고릅니다.
  - 억양은 앞뒤 문장을 보고 자동으로 정합니다.
- **키가 없을 때:** 이미지·영상은 레퍼런스 프레임과 줌 효과로, 음성은 OS 기본 음성으로 대신 만듭니다.

## 승인 알림 (원격 조정)

자동으로 도는 단계가 끝날 때마다 **승인 요청**이 생깁니다. 대상은 레퍼런스 분석, 스크립트 작성, 이미지 생성, 클립·음성 준비입니다.
- 앱 상단의 🔔 알림 센터나 해당 단계 화면의 배너에서 **[진행]** 또는 **[수정]**을 누릅니다.
  - **진행**: 다음 단계가 자동으로 시작됩니다.
  - **수정**: 코멘트가 해당 단계 화면에 표시됩니다. 스크립트 단계에서는 Claude가 코멘트를 반영해 수정본을 만들고 다시 승인을 요청합니다(API 키 연결 시).
- **Flow 메신저 연동(예정):** 같은 승인 요청이 Flow로 전송되고, 「진행 a1b2c3」 또는 「수정 a1b2c3 내용」으로 답하면 PC 앞에 없어도 다음 단계가 실행됩니다.
  - 응답을 받는 입구 `POST /api/flow/webhook`과 답장 해석기는 이미 구현되어 있습니다.
  - Flow API 문서를 받으면 `backend/notify/flow.py`의 전송 부분만 채우면 됩니다.

## 설정 (.env)

| 항목 | 기본값 | 설명 |
|---|---|---|
| `ANTHROPIC_API_KEY` | (비어 있음) | Claude API 키 |
| `ANTHROPIC_WORKSPACE_ID` | (비어 있음) | 키가 `sk-ant-usr-`로 시작할 때만 필요. 콘솔의 워크스페이스 ID(`wrkspc_…`) |
| `CLAUDE_MODEL` | `claude-opus-5-5` | 분석·생성에 쓰는 모델 |
| `STT_ENGINE` | `local` | 음성 인식 엔진. 현재는 `local`(로컬 Whisper)만 구현되어 있음 |
| `WHISPER_MODEL` | `small` | `tiny` / `base` / `small` / `medium` / `large-v3` (클수록 정확하지만 느림) |
| `HIGGSFIELD_API_KEY` | (비어 있음) | 힉스필드 키 (`키ID:시크릿`) — 이미지·영상 |
| `HIGGSFIELD_IMAGE_MODEL` / `HIGGSFIELD_VIDEO_MODEL` | GPT Image 2.5 Flare / Kling 2.5 Turbo Pro | 이미지 모델 / 영상 기본 모델 |
| `TYPECAST_API_KEY` / `TYPECAST_MODEL` | (비어 있음) / `ssfm-v31` | 타입캐스트 키 / 모델 — 음성 |
| `VISUAL_ENGINE` / `SOUND_ENGINE` | (자동) | 키가 있으면 항상 힉스필드·타입캐스트 (예전 `mock`·`system` 값은 무시·자동 정리). 테스트용 임시 엔진은 `FORCE_MOCK_ENGINES=1` |
| `FLOW_*` | (비어 있음) | Flow 메신저 연동 설정 (연동 예정) |
| `PUBLIC_BASE_URL` | `http://localhost:8000` | 알림 메시지의 링크 주소 · 외부 접속 주소 |

로컬 Whisper는 첫 실행 때 모델을 내려받습니다(small 기준 약 500MB). 그래서 첫 분석은 시간이 더 걸립니다.

## 개발 모드

화면을 수정하면서 바로 확인하려면 터미널 두 개를 엽니다.
```bash
# 터미널 1: 백엔드
cd backend && ../.venv/Scripts/python -m uvicorn main:app --port 8000 --reload   # Mac: ../.venv/bin/python

# 터미널 2: 프론트엔드 (http://localhost:5173)
cd frontend && npm run dev
```

테스트:
```bash
cd backend && ../.venv/Scripts/python -m tests.test_rules
```
